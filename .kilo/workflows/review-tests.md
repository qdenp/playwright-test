---
description: Ревью спеков playwright-tests по чек-листу качества
---

Сделай ревью качества тестов по правилам из `AGENTS.md` §3 и скила `playwright-tests`.

Аргумент: `$ARGUMENTS` — путь к файлу, каталогу (`playwright-tests/typescript/tests/e2e`)
или пустая строка = ревью всего набора TypeScript.

Что проверять по каждому файлу:

- [ ] Есть ли `expect` / `assert`? Тест без проверки — брак.
- [ ] Все ли ассерты web-first (`toHaveCount`, `toHaveText`, `toHaveURL`), а не `expect(await x())`?
- [ ] `waitForTimeout`, `try/catch` с `break`, замеры через `Date.now()`?
- [ ] Сырые `page.locator(...)` / `page.get_by_text(...)` в спеке вместо методов PO?
- [ ] Локаторы через `data-test`, а не CSS-цепочки `.btn.btn_primary...`?
- [ ] Проверяются ли итоговые суммы чекаута (subtotal / tax / total)?
- [ ] Название теста описывает поведение, а не номер?
- [ ] Тест независим от порядка выполнения?
- [ ] Не тестируется ли несуществующий в SauceDemo функционал (API товаров, edit quantity)? PDF-экспорт есть — это не нарушение
- [ ] Нет хардкода таймаутов и магических чисел?
- [ ] Отражена ли правка в остальных двух реализациях?

Оформление результата:

1. Таблица с колонками: файл:строка, категория (P0/P1/P2), проблема.
2. Отдельно блок «Что сделано хорошо» — не только минусы.
3. Сортировка от критичного к косметическому.
4. Ничего не исправляй без запроса: сначала отчёт.
5. Не перезаписывай предыдущие ревью. Если ревью крупное — сохрани его в
   `playwright-tests/TEST_REVIEW_<дата>.md` и сошлись на него в ответе.
